# lowend_arena — reference shard, tier `lowend`

A 2-player arena at 720p, minimal and measurable.

This shard exists to ANSWER the payload question with a running program:
what does a playable 720p arena actually weigh, and what does 2 MB buy?

Rules it obeys:
- 720p render target (1280x720) — the frame is generated, not promised
- Two players, integer positions, deterministic input decoding
- Sprites generated at runtime via Pillow (no external assets)
- One level (arena bounds + obstacles), encoded in the shard
- Audio: minimal PCM tone generated at runtime (no external files)
- Single-file bundle: code + shard.json manifest (content-addressed)

Why it exists: the bleeding-edge document claims Wasm 3.0, WASM-4 64 KB carts,
and iroh 1.0. This shard measures what a REAL payload weighs at the resolution
the plan cites (720p/30) so those claims can be tested against a number with a
command behind it.

## Run it

```bash
# Golden run (what the manifest declares)
python main.py --ticks 3600 --input 000102030405060708090a0b0c0d0e0f --headless

# Expected JSON output:
# {"agree": true, "headless": true, "repeat": 1, "state_sha256": "<hash>", "ticks": 3600, "token": "AZAZAEL-LOWEND-OK"}

# Verify determinism across repeats
python main.py --ticks 3600 --input 000102030405060708090a0b0c0d0e0f --headless --repeat 5

# Render frames (for visual verification)
python main.py --ticks 600 --input 000102030405060708090a0b0c0d0e0f --render-out frames/
```

The declared golden run is the first command. `--headless` changes nothing in the
hash, and that is the point: it is a real flag rather than a promise in JSON, so
the requirement the validator enforces can actually be exercised.

## What was measured, and where

| claim | how it was measured |
|---|---|
| identical hash on repeat | the command run 3 times in 3 processes, and 5 times in one (`--repeat 5`) |
| a different input gives a different hash | `ffe...00f` vs `000...00f`: hashes differ |
| tick cost | `python main.py --ticks 3600 --headless --repeat 1` measured on author box (Python 3.15t, this machine) |
| no float in authoritative state | `main.py` imports only `argparse`, `hashlib`, `json`, `sys`, `wave`, `math`, `PIL`; positions, velocities, hit tests are `int` |
| 720p frame generated | `--render-out` produces 1280x720 PNG frames |
| sprites procedural | `make_player_sprite`, `make_projectile_sprite`, `make_obstacle_sprite`, `make_level_sprite` use only Pillow primitives |
| audio procedural | `generate_tone` uses `math.sin` at 22050 Hz; no external audio files |

The tick figures are an **author-box** reading, not a GPU target measurement. The
plan's rule is that budgets are measured on the reference box and published; this
shard publishes what it has and says which box it came from. On a Steam Deck the
number will be worse, and the manifest's `p99` should be replaced by that reading
before any circle relies on it.

## What this shard does NOT prove

- **No replay verification.** The validator reads manifests; it does not execute
  shards. M-06 (deterministic play ledger and replay verifier) is unstarted, so
  the hash above is a claim with a reproduction command, not a verified artefact.
- **No netcode.** `competitive` is false; rollback is a separate concern.
- **No renderer in the shard.** The frame is generated by Pillow for measurement
  only; a production renderer would be a separate presentation layer.

## Bundle identity

`id` is `lowend-arena@sha256:<hash>`, where the hash is over the sorted
`"<path> <sha256>"` lines of `files[]`. The definition is written down because a
content address nobody can recompute is a filename with extra steps.
